WORKFLOW section — project-specific structure, content varies.

## Template Text

```
---
WHAT THIS PROJECT DOES

[Brief project description, 1-3 sentences.]

Current sub-projects:

  [Sub-Project Name]/ — [One-line description] Any request about [the kinds of request that belong here]: read [Sub-Project Name]/[SUBPROJECT]_STATUS.txt first.

  [Sub-Project Name]/ — [One-line description] Any request about [the kinds of request that belong here]: read [Sub-Project Name]/[SUBPROJECT]_STATUS.txt first.

See Workflow Files/PROJECT_INDEX.txt for file structure.
```

## Notes

Each sub-project entry ends with a trigger clause naming the kinds of request that belong to it and the status file to read before the first action. The clause sits where a request is recognized, so activation starts from the entry itself.

The domain-specific examples line in SUB-PROJECT ACTIVATION also varies by project. The sub-project list here and the status file pointers in SUB-PROJECT ACTIVATION must stay in sync.
