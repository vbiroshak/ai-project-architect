# HANDOFF.txt

Startup orientation file. Overwritten with each session log (paired writes). See the [handoff workflow section](../workflow-sections/handoff.md) for the governing rules.

## Structural Template

```
[PROJECT] HANDOFF
Last updated: [date] (Session NNN)
Last reviewed: [date]

Orientation only, not a record. The next session reads the latest session log — do not repeat or summarize it. Write only what the next session picks up or points to. Finished work goes in the session log and comes out of the handoff at the same overwrite. Rules, operating knowledge, and reference facts go in the governing documents. Preserve this header on every overwrite.

---
ACTIVE WORK

[Each item on its own line with current state, most pressing first. Sub-items indented under their header. For each area, point to what the next session needs: session logs, key documents, status of open questions.]

---
STANDING ITEMS

[Paused but ongoing work, one item per line. Not tasks — active threads that can be picked up any session.]

---
FOR DEPTH

[Which session logs to read for additional context. After structural or meta work, note which earlier sessions contain the last domain work.]
```
